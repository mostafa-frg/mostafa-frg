03 / SECURITY & TRUST

Security is a design rule.
Not a badge.

This is a static portfolio hosted on GitHub Pages. The controls below reduce browser-side risk while keeping the site auditable and free of unnecessary data collection.

STATIC SITENO BACKENDNO TRACKING SCRIPT
BROWSER POLICY

Content Security Policy

Pages use a restrictive CSP meta policy: same-origin scripts and styles, no plugins or embedded objects, no external connections and same-origin forms.

DEPENDENCIES

Minimal third parties

External font dependencies are removed. The site uses system fonts and local CSS/JavaScript assets.

NAVIGATION

Safer external links

Links opening new tabs use rel=noopener noreferrer to prevent opener access and reduce referrer leakage.

DATA HANDLING

Local-only tools

Subnet and file hashing tools run in the browser. The selected file is not uploaded.

WORKFLOW

Least privilege deployment

GitHub Actions has repository read permission and the Pages deployment permissions it requires.

TRANSPARENCY

Hosting boundaries

GitHub Pages manages HTTPS and response infrastructure. This repository cannot configure arbitrary HTTP response headers.

Hosting limitation: CSP in a meta tag cannot enforce every HTTP header directive, including frame-ancestors. GitHub Pages does not provide general custom response-header configuration. This is not an authenticated application or a security boundary.
SECURE DEVELOPMENT CHECKLIST

Ongoing maintenance

  • Keep workflow permissions minimal.
  • Review and pin third-party GitHub Actions to verified commit SHAs when practical.
  • Never commit API keys, tokens, passwords or private data.
  • Review every external script, embed, font and analytics dependency.
  • Protect the GitHub account with MFA or passkeys and review collaborators.
  • Run tests and inspect deployment results after each release.
