03 / SECURITY & TRUST

Security is a design rule.
Not a badge.

This site has two deployment surfaces: a public static portfolio on GitHub Pages and a Cloudflare Worker that serves the same site with the authenticated API and D1-backed workspace. Account operations run only on the Worker origin.

BROWSER POLICY

Content Security Policy

HTML pages use a restrictive CSP meta policy. The Cloudflare Worker additionally sends frame-denial and other security headers on static responses; the GitHub Pages mirror uses provider-managed response headers.

DEPENDENCIES

Minimal third parties

External font dependencies are removed. The site uses system fonts and local CSS/JavaScript assets.

NAVIGATION

Safer external links

Links opening new tabs use rel=noopener noreferrer to prevent opener access and reduce referrer leakage.

DATA HANDLING

Local-only tools

Subnet calculation, file hashing, Config Audit and HTTP Header Audit operate in the browser or the authenticated Worker API as documented. Selected files and pasted audit input are not uploaded by the browser-side tools.

WORKFLOW

Least privilege deployment

GitHub Actions validates the portfolio and deploys the static mirror and Cloudflare Worker. Cloudflare credentials are stored as repository secrets, not committed to source.

TRANSPARENCY

Hosting boundaries

The Cloudflare Worker serves the authenticated API and D1-backed workspace from the same origin as its portfolio assets. GitHub Pages is a static mirror and cannot provide the same-origin API or custom response-header configuration.

Hosting boundary: The GitHub Pages mirror is public and static; it is not an authentication boundary and does not serve the API. Platform access is forwarded to the Cloudflare Worker. A meta CSP cannot enforce frame-ancestors, so the Worker adds that directive as an HTTP response header. GitHub Pages response headers remain provider-managed.
SECURE DEVELOPMENT CHECKLIST

Ongoing maintenance

  • Keep workflow permissions minimal.
  • Review and pin third-party GitHub Actions to verified commit SHAs when practical.
  • Never commit API keys, tokens, passwords or private data.
  • Review every external script, embed, font and analytics dependency.
  • Protect the GitHub account with MFA or passkeys and review collaborators.
  • Run tests and inspect deployment results after each release.
